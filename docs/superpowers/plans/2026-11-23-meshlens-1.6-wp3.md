## Decisioni di progetto (vincolanti per i task)

**D1 — Stato degli strati fuori da `viewstate.ts`.** `viewstate.test.ts` (file di WP0, non modificabile) confronta con `toEqual` l'intero `ViewState` predefinito: aggiungere un campo `layers` lo romperebbe. Lo stato degli strati sta quindi in `W/lib/map/layerstate.ts` con chiave propria `meshlens.layers` (versione 1), stessa filosofia di `loadView` (ogni campo non valido torna al predefinito). `viewstate.ts` non cambia in WP3 (la vista `topology` è già in `NetView` grazie a WP0).

**D2 — Raggi di precisione senza poligoni.** Per ogni nodo con `precision_bits` tra 1 e 15 (stessa regola di `geo.precisionRadiusM`) si emette un punto con `r_m` e `px22`, dove `px22 = r_m / (0.037322767717 · cos(lat))` (metri per pixel a zoom 22 alla latitudine del nodo: `156543.03392 · cos(lat) / 2^22`). Il layer `circle` usa `circle-radius = ['interpolate', ['exponential', 2], ['zoom'], 0, 0, 22, ['get', 'px22']]` (errore < 0,1 % per zoom ≥ 8), con `circle-pitch-alignment: 'map'`. Il Task 7 **valida l'espressione con lo style-spec di MapLibre** (`createPropertyExpression`, tipo `composite`); se la validazione fallisce, ripiego prescritto: layer `fill` con `circlePolygon(lat, lon, r, 24)` solo per i nodi nel riquadro visibile, solo da zoom 9, tetto 1500 poligoni. Layer con `minzoom: 8`; tetto 3000 feature (si tengono quelle col raggio maggiore).

**D3 — Mappa di calore.** Sorgente `heat` (punti non raggruppati, una feature per nodo con posizione, nessuna proprietà), layer `heatmap` con `heatmap-weight: 1`, raggio interpolato per zoom (12 px a zoom 3 → 40 px a zoom 12), intensità crescente con lo zoom, `heatmap-opacity` che scende da 0,85 (zoom ≤ 9) a 0,35 (zoom ≥ 12) per non coprire i nodi; rampa colori dai token (`transparent → srcRadio → contactRecent → snrBad`). Tetto 20 000 punti. Inserito sotto `precision-fill` (quindi sotto cluster, nodi e icone).

**D4 — "Solo infrastruttura".** Filtro **solo della mappa** (non di `app.filter`, che è condiviso con elenco e statistiche e salvato da `stores.svelte.ts`, congelato): `isInfrastructure(n)` in `filters.ts` = `n.role ∈ INFRA_ROLES = {ROUTER, ROUTER_CLIENT, ROUTER_LATE, REPEATER}` (nomi dell'enum `Config.DeviceConfig.Role` della libreria 2.7.11, già i valori salvati in `nodes.role`). `MapView` calcola `shown = layers.infra ? nodes.filter(isInfrastructure) : nodes` e lo usa per nodi, calore, cerchi, collegamenti (`linksToGeoJSON` salta già i link con un estremo assente) e "adatta ai nodi". Non si toccano `NodeFilter`, `loadFilter`, `saveFilter`.

**D5 — Etichette dei collegamenti.** `linksToGeoJSON` aggiunge la proprietà `label` (additiva) costruita da `linkLabel(snr, source, fmt)`: `"−7,5 dB"`; per `rf_direct` (ricezione diretta = 0 salti) `"−7,5 dB · diretto"`; senza SNR e senza salti noti → stringa vuota (nessuna etichetta). I collegamenti non portano altra informazione di salti (il contratto non estende `links`): **il "hop" dell'etichetta è quindi solo "diretto" per `rf_direct`**; i salti dei nodi restano nel popup del nodo. Layer `symbol` `links-labels` sulla sorgente `links` (`symbol-placement: 'line-center'`, `text-optional`, `text-padding: 4`, `minzoom: 9`, `minzoom: 11` se le feature con etichetta sono più di 800); richiede i glyph (come `cluster-count`): senza glyph il layer non esiste e `LayerPanel` disabilita la riga con spiegazione.

**D6 — Grafo della topologia.** Un arco non orientato `{u, v}` (u ≠ v) esiste se la tabella `links` ha almeno una riga nella finestra, in uno dei due versi, per una delle sorgenti scelte (`neighborinfo`, `traceroute`, `mqtt_gateway`, `rf_direct`; predefinito tutte). Le sorgenti dello stesso arco si fondono (elenco), SNR = massimo, tempo = massimo. L'universo dei nodi V e gli isolati sono definiti nel Task 4. **Algoritmo di analisi** (tutto in `topology.analyze`, tempo O(V+E), **iterativo**, nessuna ricorsione):

1. Grafo semplice: lista di adiacenza ordinata per numero del nodo; self-loop scartati; archi doppi fusi.
2. Per ogni radice non visitata, in ordine crescente di numero, DFS con pila esplicita di `(nodo, indice del prossimo vicino)`. Al primo ingresso in `v`: `disc[v] = low[v] = timer++`, `sz[v] = 1`, il figlio entra con `parent[w] = v`.
3. Per ogni vicino `w` di `v`: se `w == parent[v]` si salta (grafo semplice: basta un salto); se `w` già visitato: `low[v] = min(low[v], disc[w])`; altrimenti si scende in `w`.
4. Quando `w` ha esaurito i vicini e si torna al padre `v`: `low[v] = min(low[v], low[w])`, `sz[v] += sz[w]`; se `low[w] >= disc[v]` il sotto-albero di `w` si stacca togliendo `v`: si aggiunge `sz[w]` a `sep[v]` (lista) e a `sep_sum[v]`.
5. Fine della componente (radice `r`, dimensione `comp_size = sz[r]`): per ogni nodo `v` della componente i **pezzi** che restano togliendo `v` sono `sep[v]` più, se `rem = comp_size − 1 − sep_sum[v] > 0`, il pezzo `rem` (la parte che contiene la radice; per la radice vale `rem = 0`). **`v` è punto di articolazione se e solo se ci sono almeno 2 pezzi.** `impact[v] = comp_size − 1 − max(pezzi)` = numero di nodi che perdono il collegamento con il pezzo più grande (0 se non è cerniera).
6. Componenti numerate nell'ordine di scoperta (la più grande ottiene `component = 0` dopo una rinumerazione per dimensione decrescente, a parità per numero del nodo più piccolo); `degree[v]` = numero di vicini.
7. **Hub:** sia `d` la lista ordinata dei gradi positivi; soglia `thr = max(4, d[ceil(0,9·len(d)) − 1])` (percentile 90 per rango più vicino); `hub = degree ≥ thr`. **Isolati:** nodi di V (con riga in `nodes`, `last_heard ≥ since`) con `degree == 0`; non fanno parte del disegno (elenco a parte).
8. Le statistiche e le cerniere si calcolano **sempre sul grafo intero filtrato**; solo l'*uscita* è troncata (Task 4: `limit`, priorità cerniere per impatto, hub, grado).

**D7 — Decodifica ATAK.** `TAKPacket.FromString`; con `is_compressed` vero i testi (`contact.callsign`, `contact.device_callsign`) sono illeggibili → `NULL`. Se l'intero messaggio non è analizzabile (testi compressi con byte non UTF-8: il parser protobuf li rifiuta) si ripiega su un lettore a mano del formato binario che estrae solo i campi 1 (`is_compressed`), 3 (`group`), 4 (`status`), 5 (`pli`) e analizza ognuno con la propria classe: così posizione, squadra, ruolo e batteria si leggono comunque (la ricerca §6 dice che i campi numerici si leggono). Nomi di squadra e ruolo = `Team.Name(v)` / `MemberRole.Name(v)` come nella libreria (`Cyan`, `TeamMember`…); i valori "non specificato" (0: `Unspecifed_Color`, `Unspecifed`) diventano `NULL`. Posizione `(0, 0)` o fuori scala = senza fix (`lat`/`lon` `NULL`). Solo i pacchetti con il campo `pli` (5) creano/aggiornano un contatto; chat e `detail` soli si ignorano. **ATAK v2 (portnum 78) e `ATAK_FORWARDER` (257) non sono decodificati** (contratto §4.1): si segnalano con un conteggio dei pacchetti 78 nel registro pacchetti (`/api/tak/summary`).

```ts
export type SnrClass = 'good' | 'mid' | 'bad' | 'none'
export const snrClass = (snr: number | null): SnrClass     // >= 0 good, >= -10 mid, altrimenti bad, null none (stessi limiti di snrColor)
export interface Pt { x: number; y: number }
export function layout(nodes: Pick<TopologyNode, 'id' | 'degree'>[], edges: Pick<TopologyEdge, 'a' | 'b'>[],
                       opts?: { width?: number; height?: number; seed?: number; iterations?: number }): Map<string, Pt>
export interface ViewBox { x: number; y: number; w: number; h: number }
export function fitViewBox(points: Pt[], pad?: number, aspect?: number): ViewBox
export function zoomAt(vb: ViewBox, factor: number, cx: number, cy: number, min?: number, max?: number): ViewBox
export function panBy(vb: ViewBox, dx: number, dy: number): ViewBox
export function neighborsOf(edges: TopologyEdge[], id: string): string[]          // ordinati
export function listCuts(r: TopologyResult): TopologyNode[]                        // cut, per impact decrescente poi nome
export function listHubs(r: TopologyResult): TopologyNode[]                        // hub non cut, per grado decrescente
export function needsNeighborInfoHelp(r: TopologyResult): boolean                  // by_source.neighborinfo === 0
```

Layout (algoritmo vincolante): Fruchterman–Reingold deterministico su un'area `width × height` (predefinita 1000 × 700).
1. PRNG `mulberry32(seed)` con `seed` predefinito = hash FNV-1a a 32 bit dell'elenco degli id ordinati e uniti da `|`; ordine di elaborazione = id ordinati (risultato indipendente dall'ordine dell'input).
2. Posizione iniziale: nodo `i` di `n` su un cerchio di raggio `0.35·min(width, height)` all'angolo `2πi/n + jitter` (jitter ∈ ±0,1 rad dal PRNG).
3. `k = 0.9·sqrt(width·height / n)`; per ogni iterazione: repulsione tra **tutte** le coppie `k²/d`, attrazione lungo gli archi `d²/k` (peso 1), gravità verso il centro `0.02·d`; spostamento limitato alla temperatura `T = (width/10)·(1 − it/iterations)`; posizioni confinate in `[pad, width−pad]` e `[pad, height−pad]` (`pad = 24`).
4. `iterations` predefinite: `n ≤ 150 → 300`, `n ≤ 400 → 180`, altrimenti `120`; `n = 0 → Map vuota`, `n = 1 → centro`; coppie coincidenti (`d < 1e-6`) si separano con una spinta casuale dal PRNG (mai NaN).
